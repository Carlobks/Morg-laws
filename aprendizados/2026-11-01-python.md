# Python

## O `python` do PATH pode não existir, ou ser outro

**O que aconteceu:** num Windows, `python` abria a loja ou um interpretador diferente do esperado; um arquivo da pasta com o nome de um módulo da biblioteca padrão rodou no lugar dele.
**Como fazer:** no Windows, chame o lançador (`py`, ou `C:\Windows\py.exe`); em scripts portáveis, `MORG_PY`, depois `py`, depois `python3`. Sempre com `-I`: ignora a pasta atual e as variáveis `PYTHON*`. Com `-I`, a pasta do script também sai do `sys.path`: um script que importa um vizinho faz `sys.path.insert(0, pasta_do_script)` antes.

## `UnicodeDecodeError` é um `ValueError`, não um `OSError`

**O que aconteceu:** um arquivo de configuração gravado em ANSI por um editor antigo passou pelo `except OSError` e derrubou o programa no arranque, sem log.
**Como fazer:** ao ler arquivos escritos por pessoas, use `except (OSError, ValueError)` e caia para a página de código local (`cp1252`) se fizer sentido.

## `urlparse(...).port` lança erro ao ler, não ao analisar

**O que aconteceu:** o `try` à volta do `urlparse` não pegou uma porta errada (`:30000a`, `:99999`).
**Por que:** o erro só aparece ao ler o atributo `.port`.
**Como fazer:** leia `.port` dentro do `try`.

## No ctypes, uma função sem `restype` corta os ponteiros

**O que aconteceu:** `kernel32.GetModuleHandleW(None)` devolvia `0xffffffffea740000` em vez de `0x7ff6ea740000`; as funções que recebiam esse handle davam "access violation" a cada arranque, que o próprio Windows engolia. Só apareceram quando o programa passou a ligar o `faulthandler`.
**Por que:** sem `restype`, o ctypes devolve um `int` de 32 bits.
**Como fazer:** declare `restype` e `argtypes` de cada função que devolve um handle ou um ponteiro. Um teste pode exigir isso para a lista de funções usadas.

## Rodar um script como programa no processo do teste herda o que ele instala

**O que aconteceu:** um teste rodava um script com `runpy` como `__main__`; o script passou a instalar um gancho global de exceções e o `faulthandler`, que ficaram no processo dos testes e criaram arquivos na pasta pessoal real.
**Como fazer:** nesses testes, simule o que mexe no processo ou no computador e confira que é chamado; num subprocesso, aponte a pasta pessoal para uma pasta temporária. Depois de mexer no arranque de um script, veja se os testes deixaram arquivos para trás.

## No Windows, `Path.write_text` grava CRLF

**O que aconteceu:** um script de testes montou arquivos com `write_text` e o teste de fins de linha acusou quatro arquivos em CRLF.
**Por que:** em modo texto, o Python troca `\n` pelo fim de linha do sistema.
**Como fazer:** grave bytes (`write_bytes(texto.encode("utf-8"))`) ou passe `newline="\n"`.
